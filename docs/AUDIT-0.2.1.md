# Ember 0.2.1 reliability audit

The earlier LFM3 build could spend all 512 allowed tokens on hidden reasoning. Saved failed requests confirmed a length stop with no visible answer. Simple HTML could also be cut off by the ordinary answer limit, even though Canvas was available.

The native runtime now bounds reasoning separately from answer generation. Short answers allow 32 reasoning tokens; long/code answers allow 128. Code requests and follow-up edits receive up to 2,048 answer tokens with Canvas either on or off. Failed and interrupted turns are excluded from subsequent prompts. Response outcomes are persisted, and retry replaces the last attempt while preserving its web-search intent and any attached repair source.

Canvas reports JavaScript errors and offers **Fix with Ember** when the model is ready. This sends the exact current source and error in a new request. The source appears as a file attachment, so the chat does not expand into a large pasted code block. Downloads preserve the source without document wrappers. Automatic repair is limited to small files that fit the model's context.

App-owned light and dark surfaces now specify Material's remaining accent, inverse, error and container colors. Menus, sheets and dialogs inherit this palette. Panels have a close action; the file editor respects screen/keyboard insets; response actions use larger touch targets; file cards show progress while writing. A generated page keeps its own CSS colors. System permission and document-picker surfaces belong to Android.

Validation uses the personal development package on an Android 16 arm64 CMF Phone 2 Pro, updated in place. Unit tests cover download recovery/integrity, code parsing, budgets, context filtering, repair source and retry intent. Phone tests cover file generation with Canvas off, light/dark panels, file editors, cancellation/retry, source repair, Canvas isolation/touch input, exact-source download and scrolling. The separate native test covers facts, arithmetic, multi-turn recall, cancellation and switching between Liquid and Bonsai. QA removes its own chats/download fixtures and checks that existing nonempty chats are unchanged. Private captures, weights and app data are excluded from Git.

Model quality remains a separate limit. The small gradient-button request completed and ran. A larger driving-game request produced a complete file but referenced an undefined variable; Canvas surfaced the error. The large-game regression therefore requires file completion and error visibility, rather than claiming that any game generated by a 1.7B model is correct. Basic generated HTML and the repair fixture are checked under real touch input. More complicated code can still need iteration, and a successful repair is not guaranteed.

Final verification: the debug build, all 16 JVM tests, and the five selected device tests passed. The separate native inference/switching test also passed. Lint reported zero errors (20 warnings and four hints remain, largely dependency/toolchain and style suggestions). The installed APK's SHA-256 matched the local build, all 21 existing nonempty chats were preserved, and the memory database's checksum was unchanged. A wrong-package installer probe was rejected before adb could install anything.

Phonon speech-to-text is not included in this repair release.
